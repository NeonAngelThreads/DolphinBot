# 6. 包监听器

当 `@EventHandler` 语义不够时，`getListeners()` 让你直接拿到流经会话的原始 MCProtocolLib 包。Actions-Core 里的 `WorldCache`、`InventoryCache` 等被动模型全部基于这个机制。

## 添加监听器

```java
@Override
public void onEnable(RobotPlayer bot) {
    getListeners().add(
        new LoginHandler().addExtraAction(pkt -> {
            var spawn = pkt.getCommonPlayerSpawnInfo();
            getLogger().info("加入维度=" + spawn.getDimension());
        })
    );
}
```

`getListeners()` 返回 `Iterable<AbstractEventProcessor>`。每个处理器监听**特定包类型**，运行默认行为后可链式 `.addExtraAction(...)` 添加回调。

## 内置处理器

| 处理器 | 目标包 | 典型用途 |
|--------|--------|---------|
| `LoginHandler` | `ClientboundLoginPacket` | 读取维度、游戏模式、出生点 |
| `JoinedGameHandler` | — | 加入游戏后的钩子 |
| `SystemChatHandler` | `ClientboundSystemChatPacket` | 读取服务器消息 |
| `PlayerLogInfo.UpdateHandler` | — | 玩家列表更新 |
| `PlayerLogInfo.RemoveHandler` | — | 玩家列表移除 |

> [!TIP] Lambda vs 命名类
> `.addExtraAction` 接受 lambda 或接口实现。一行代码用 lambda；长处理器或需要字段时用命名类。

## 自定义处理器

继承 `AbstractEventProcessor<TargetPacket>` 并覆盖 `isTargetPacket`：

```java
public class ChatLogHandler extends AbstractEventProcessor<ClientboundPlayerChatPacket> {
    @Override
    protected boolean isTargetPacket(Packet packet) {
        return packet instanceof ClientboundPlayerChatPacket;
    }
}
```

注册方式同上：

```java
getListeners().add(
    new ChatLogHandler().addExtraAction(pkt -> {
        getLogger().info("[聊天] " + pkt.getContent());
    })
);
```

## 为什么不能监听所有包？

技术上可以：

```java
getListeners().add(new AbstractEventProcessor<Packet>() {
    @Override protected boolean isTargetPacket(Packet packet) { return true; }
});
```

但不应该——每个包都会分配事件包装器。请指定目标包类型，框架分发效率很高。

## Actions-Core 是最好的参考

`WorldCache` 和 `InventoryCache` 都是包监听器。它们订阅区块、实体、背包包并保持状态更新——没有轮询。见 [Actions-Core 世界模型](../docs_CN/12-Actions-Core-世界模型.md)。
