# 3. 插件生命周期

每个插件实例遵循相同的三阶段生命周期。理解它是写对插件的关键。

## 状态机

```
┌──────────┐ onLoad() ┌────────────┐ onEnable(bot)  ┌────────────┐ onDisable()   ┌─────────┐
│ NOT LOAD ├─────────►│  LOADED    ├───────────────►│  ENABLED   ├──────────────►│ DISABLED│
└──────────┘          └────────────┘                └────────────┘               └─────────┘
       │                       │                               ▲
       │ 插件后来被添加         │ 同一个 Bot Profile 再次加入    │
       └───────────────────────┴───────────────────────────────┘
```

## 三个钩子

| 钩子 | 运行时机 | 可用的上下文 | 典型用途 |
|------|---------|-------------|---------|
| `onLoad()` | JAR 首次被发现时 | 仅有插件元数据——**没有 Bot** | 注册 SPI 实现、缓存不可变数据 |
| `onEnable(RobotPlayer bot)` | **每个 Bot Profile** 加入服务器时 | `bot` 句柄、`getListeners()`、`getCommands()`、`getLogger()` | 注册包监听器、命令、状态机 |
| `onDisable()` | Bot 断开连接或关闭时 | 与 onEnable 相同，但 bot 可能已断开 | 停止队列、清理状态 |

## `onLoad()` — 单例阶段

`onLoad()` **每个 JAR 只调用一次**，而不是每个 Bot 一次。适合做：

- 注册全局 SPI（如 `RobotPlayer.registerActionSimulator(...)`）
- 缓存不可变数据（配置解析、注册表查询）
- 不依赖特定 Bot 的插件级单例

```java
@Override
public void onLoad() {
    // 单例注册
    RobotPlayer.registerActionSimulator(this.simulator);
    this.commandManager = getTerminalCommands();
}
```

> [!WARNING] onLoad 里没有 Bot
> `RobotPlayer`、`getListeners()`、`getCommands()` 在 onLoad 阶段**还没有意义**。不要在这里订阅包事件——此时还没有会话。

## `onEnable(bot)` — 每 Bot 装配

每次 Bot Profile 加入服务器时都会运行。所有需要与**特定 Bot** 交互的东西都在这里：

```java
@Override
public void onEnable(RobotPlayer bot) {
    var worldCache = new WorldCache();
    getListeners().add(worldCache);
    getListeners().add(new LoginHandler().addExtraAction(pkt -> ...));

    getTerminalCommands().registerCommand(new TerminalCommand.Builder()
        .withName("hello")
        .withProvider(this)
        .build((r, b) -> getLogger().info("嗨！")));
}
```

## `onDisable()` — 清理

Bot 断开（踢出、服务器停机、手动关闭）时调用。最常见的清理动作是停止串行执行器：

```java
@Override
public void onDisable() {
    if (this.context != null) {
        this.context.queue().shutdown();
    }
    getListeners().clear();
}
```

> [!WARNING] onDisable 可能抛异常
> 如果你的 onDisable 内部抛异常，框架会吞掉这个调用。关键清理要加 try/catch 或做幂等设计。

## 每 Bot vs 全局——心智模型

| 作用域 | 机制 | 示例 |
|--------|------|------|
| **全局（每 JAR）** | `onLoad()` 字段、static 状态 | SPI 注册、配置、共享注册表 |
| **每 Bot** | `onEnable(bot)` 创建新状态 | `ActionQueue`、`WorldCache`、`InventoryCache` |

**经验法则**：如果数据依赖 `bot.getPosition()`、`bot.getSession()` 或 Bot Profile 名——它就是每 Bot 的。如果它是不关心哪个 Bot 的共享常量或类——它就是全局的。

> [!TIP] Actions-Core 是最好的参考
> 看 `ActionsCorePlugin.onLoad()` vs `onEnable()` 的源码，这是正确拆分的范例。

## 登录时机

在 `onEnable` 内部还有两个时间点：

1. **会话打开** — `onEnable` 在 TCP 连接建立后立即调用
2. **登录完成** — Bot 收到 `ClientboundLoginPacket` 并生成后

如果你的插件需要知道 Bot 的维度、游戏模式或出生点，在 `onEnable` 里订阅 `LoginHandler` 监听首次登录包：

```java
@Override
public void onEnable(RobotPlayer bot) {
    getListeners().add(new LoginHandler().addExtraAction(loginPacket -> {
        var spawn = loginPacket.getCommonPlayerSpawnInfo();
        getLogger().info("维度: " + spawn.getDimension());
    }));
}
```
